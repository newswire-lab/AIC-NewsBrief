# scripts/_archive —— 一次性探查脚本归档

**这里不是死代码回收站，而是"每一步结论都能回去查证"的证据链。**

本目录下的脚本都是开发过程中为回答某个具体问题而临时写的探查/回归脚本
（例如"关键词标签为什么在两次运行间不一致""检索为什么搜不到某个来源"
"简报为什么被降级"）。它们的价值不在于被复用，而在于**每一条写进
技术报告的实测结论，都能在这里找到当时是怎么测出来的**。

所以采取的是**归档而非删除**。

## 使用前必读

1. **路径已改写。** 原脚本硬编码了编写者的本机绝对路径
   （形如 `C:\Users\<用户名>\...`），这会被 `scripts/check_anonymize.py`
   判为匿名化违规（本作品的提交材料要求不得出现可识别身份的信息）。
   归档时统一改为：

   ```python
   import os as _os
   _ROOT = _os.path.dirname(_os.path.dirname(_os.path.dirname(_os.path.abspath(__file__))))
   _DESKTOP = _os.path.join(_ROOT, "logs", "_archive_out")
   ```

   `_ROOT` 即项目根；原本输出到桌面的中间结果改写到
   `logs/_archive_out/`（该目录已被 `.gitignore` 忽略，不会再污染桌面）。

2. **不保证逐条可原样复跑。** 这些脚本依赖当时的数据库状态与源码版本
   （例如 `test_kw.py` 断言的标签数量是当时那批数据的结果）。
   要看结论请优先读 `docs/技术报告.md` 与 `docs/技术报告.md`。

3. **同批归档的数据文件**在 `logs/_archive/`（含关键词转储
   `_kw_dump_*.json`、各次回归的文本输出）。该目录同样不入库。
