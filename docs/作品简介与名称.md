## 作品简介（正文 292 字符，≤ 300）

同一事件经多家媒体转载改写常互相矛盾，读者难判断"有几家独立信源"。

**问题**：多源公开新闻缺可核验的当日聚合，生成式摘要又常有幻觉。

**方案**：自研"采集—归并—评分—生成—校验"流水线。增量采集用条件请求；
三阶段归并（内容指纹、标题 SimHash、IDF 加权语义相似度）；
"权威度×时效性×交叉印证"打分，印证度按机构去重。

**实现**：本地部署开源模型 Qwen2.5-3B（4-bit）生成标题、价值点与 300 字简报，
强制每句标注依据编号；校验器逐句核对原文覆盖率，不通过即降级为抽取式摘要。

**效果**：单日聚合 3500 余条，剪枝后仅比对 2.65%。

**开放成果**：MIT 许可源码、源配置、标定脚本与合规文档。

## 字数校验（2026-09-29 复核）

⚠️ **曾存在超限问题**：简介在「去军事化」改写后变长，而文中标注仍为旧值 287 字。
2026-09-29 实测为 **汉字 304 / 汉字+标点 340 / 不计空格 421** ——
**三种口径全部超过 300 字上限**，现已压缩改写。

| 口径 | 现行 | 上限 | 判定 |
|---|---|---|---|
| 中文汉字 | 210 | 300 | ✅ |
| 汉字 + 中文标点 | 244 | 300 | ✅ |
| **不计空格总字符（最严）** | **292** | 300 | ✅ 余量 8 |

- 校验方式：去掉 Markdown 加粗标记 `**` 后统计，不计算空白字符
- 复算命令（退出码 0 = 合规，1 = 超限，可直接做提交门禁）：

```powershell
python scripts/check_brief_length.py            # 加 --verbose 可看逐行统计
```

- **提交前务必再跑一次**：300 字是硬性上限，
  且在线提交表单可能按「不计空格字符数」截断，因此按最严口径留出余量。
