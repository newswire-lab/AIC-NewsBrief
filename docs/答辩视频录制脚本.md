# 答辩视频录制脚本（国赛 · 全国半决赛）

> 依据《关于举办第八届全球校园人工智能算法精英大赛算法主题赛全国半决赛的通知》（全智赛组委会〔2026〕83 号）附件《比赛流程》整理。
> 本文件由 `scripts/make_record_script.py` 从 `dist/AIC-NewsBrief-答辩-国赛.pptx` 的演讲者备注自动生成，改 PPT 备注即可同步更新。

## 一、硬性规则（违反即无效或扣分）

| 规则 | 具体要求 |
|---|---|
| 录制工具 | **腾讯会议**录制，不能用本地录屏软件 |
| 出镜 | 全体队员进入会议并**开启摄像头**，全程在线出镜，画面能清晰识别每个人 |
| 人员一致 | 出镜人员必须与报名系统一致，**不符视为作弊** |
| 开场 | 视频开始后，先由团队代表清晰报出**团队名称** |
| 顺序 | 对照**评分表打分项顺序**汇报：每页 kicker 标「第几项 / 分值」，右上角四段导航（① 背景 → ② 创新点 → ③ 作品介绍 → ④ 展望）标当前进度 |
| 时长 | 汇报 + 演示 **≤ 6 分钟**；本脚本目标 **4:50**（同时满足初赛 3~5 分钟口径） |
| 后期 | **无快进、无剪辑、无遮挡**，一镜到底 |
| 画面 | PPT 共享屏幕与出镜人员**在同一画面内** |
| 环境 | 全程安静，不允许出现视频遮挡 |

## 二、录制前 5 分钟检查

- [ ] 腾讯会议：开启「共享屏幕 → 共享 PPT 窗口」，勾选**同时共享电脑声音**（若演示有声音）
- [ ] 布局切换到「宫格视图」，确认 3 人画面 + PPT 同框，且 PPT 字号看得清
- [ ] 关闭微信 / QQ / 邮箱弹窗与系统通知，手机静音
- [ ] 桌面只留 PPT 窗口，避免露出与作品无关的文件名、聊天窗口
- [ ] 电脑桌面背景、会议昵称**不得含学校名、指导老师姓名**（会议昵称建议改为队员姓名）
- [ ] PPT 第 9 页已插入演示录屏，设为自动播放
- [ ] 准备计时：手机秒表放画面外，或队友用另一台设备看时间并用手势提示

## 五、逐页口播词

> 方括号内是配速提示，不要念出来。带「口播：」的是可以直接照着读的话。

### 第 1 页 · 多源新闻聚合与可溯源简报智能体

```
口播：「评委老师好，我们的团队名称是「孤寡」，作品是多源新闻聚合与可溯源简报智能体。
我们不做又一个新闻 App，只回答一个可验证的问题——这条信息，有几家独立机构在说。」
要点：开场先报团队名称（通知要求），然后一句定位，不要念 PPT 标题。
```

### 第 2 页 · 问题：「多家报道」这件事，被系统性高估了

```
口播：先说场景——读者看到十条转载，其实可能只有一家在讲。我们统计了全库 2,551 个事件，
234 个有多个站点，但真正的两家以上独立机构只有 18 个，占 0.7%。所以「多家报道」这件事
是被系统性高估的。第二个硬伤是 AI 摘要会幻觉，你没法逐句核对它到底从哪来。
这两点就是我们要解决的问题，也是评分的第一个打分项。
```

### 第 3 页 · 一条能逐句校验的流水线

```
口播：问题清楚了，它怎么跑？八步流水线：采集、去重、事件聚类、剪枝、可信度、简报生成、
逐句校验、不过就降级。前面六步全部自研，只把「写」这一步交给开源模型，
最后一步是逐句校验，校验不过就不发，退回原文摘录。
这样做的目的只有一个：产物里每一句话都能指回具体原文。
```

### 第 4 页 · 关键在这四处：每一处都堵上一步的漏洞

```
口播：四个自研点，我挑三处说。一是聚类加剪枝，只对可能重复的组合算相似度；
二是机构级去重，这条最影响结论——防务新闻那五家其实是同一个出版集团，
按站点算会被虚报成 6 家印证，按机构算只计 1 家。三是无词典新词发现。
这两点合起来，才让「可信度」这个数字站得住。
```

### 第 5 页 · 边界：AI 只负责「写」，其余全部自研

```
口播：AI 和开源的边界我们划得很清楚。开源模型只负责写这一段，其余全部自研，
所以把模型换掉，作品照样成立。
反向也说明一下：分词、相似度、去重这些库我们都主动没用，是自己实现的。
许可方面：模型是 Apache-2.0，权重不分发，仓库里给下载脚本和 SHA256 校验。
```

### 第 6 页 · 成品：六个页签，全部可点可查

```
口播：三处不同说完了，看它实际的样子。左边是简报生成，先按机构数和时间窗筛出事件，
生成后每一句都标出依据；右边是证据链，这个事件有 7 篇报道、来自 2 个站点，
每条报道都能点回具体的原文。截图取自 2026-11-18 真机运行。
界面一共 6 个页签，都可以现场操作。
```

### 第 7 页 · 效果：这些数字都能复现

```
口播：这些数字都能复现。采集到 3,707 篇、2,551 个事件；剪枝后只比对 2.65% 的候选对；
简报 7 句全部有原文依据，217 字，生成 12 秒、含校验 34 秒。
更重要的是过程：跑真实数据时暴露出 8 个缺陷，我们逐个修掉并留了记录，
比如并列时按名称排序会让某个机构永远排前面，这是一个隐性偏见。
```

### 第 8 页 · 开放：能拿走，也能复现

```
口播：成果已经全部公开，MIT 许可，110 个文件，包括对照实验的原始输出，
评审可以直接核对。
复用上，解析、去重、相似度这三个模块是纯标准库实现，可以单独拿走用。
维护上，配置都参数化了，后面会向上游项目提 Issue 和补丁。
```

### 第 9 页 · 作品演示（约 30 秒录屏）

```
口播（播放前）：「下面用三十秒演示核心流程。」
—— 播放本页嵌入的录屏，不要现场敲命令，避免环境意外 ——
播放结束后接：「演示到这里，回到结论。」
※ 正式录制前请把录屏插入本页（插入 → 视频 → 此设备），并设为自动播放。
```

### 第 10 页 · 局限与后续：如实说明

```
口播：最后如实说三个局限。第一，跨机构印证只有 0.7%，它能说明口径有效，但不足以支撑统计结论。
第二，语料偏英文防务类，中文源摘要太短，模型直出通过率低。第三，端侧 3B 有上限，长素材还得降级。
后续做时间线、移动端和开放式评测集。汇报完毕，谢谢评委老师。
★ 总时长控制在 4 分 50 秒，不要超 5 分钟。
```

## 六、录完之后

- [ ] 回看一遍：确认**从头到尾没有剪辑点**、没有黑屏跳变、没有被弹窗遮挡
- [ ] 确认开场第一句报出了团队名称
- [ ] 确认时长为 **4:50 左右，且不超过 6 分钟**（同时控制在 3~5 分钟内更稳妥）
- [ ] 导出 MP4，体积控制在 300 MB 以内（1080p / 30fps 通常 100~200 MB）
- [ ] 上传到报名系统**【视频类文件】**栏目，截止 **11 月 19 日 23:59**
- [ ] 上传后**下载一次自己的视频**，确认能正常播放（防止上传损坏）

## 七、常见导致无效的情况

1. 用了剪映 / OBS 录屏并做了剪辑 —— 通知明确「一试发现视为无效作品」；
2. 只有主讲出镜，其他队员只开麦不开摄像头；
3. PPT 里出现校名、校徽、学院简称、指导老师姓名（确需出现要**提前**发邮件到赛题负责人邮箱报备，地址见官方通知）；
4. 超时 —— 汇报 + 演示超过 6 分钟；
5. 逾期 —— 11 月 19 日 23:59 之后无法补交。
